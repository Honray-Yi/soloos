# SoloOS 简易版｜只用提示词

不用安装 Skill，不用 Python、数据库或 API。把这里的文本复制到支持长文本的 AI 对话中，即可组织一次经营分析。默认中文，也可以在个性化设置里改成其他语言。

**这是文字工作流，不是自动运行的软件。** 八个角色是同一个 AI 的不同分析视角，不代表八个独立员工或八次独立验证。它不会自动读取其他对话、保存历史、定时运行或操作业务账户。

## 三分钟开始

1. 复制 [00-controller.txt](00-controller.txt) 到新对话中。
2. 继续粘贴 [01-principles.txt](01-principles.txt)，并填写 [02-company-profile.txt](02-company-profile.txt)。不知道的地方保留“未知”。
3. 按需要粘贴一至三个 [roles](roles/) 中的角色文件；不必每次加载全部八个。
4. 写下具体问题，或复制 [workflows](workflows/) 中的任务提示词。AI 先说明使用哪些角色，再分析。
5. 把重要结论复制到自己保存的 [决策记录](templates/decision-log.txt)。下次对话手动附上，不能假设 AI 记得。

想先体验一次，可以使用 [虚构案例](examples/quick-start.txt)，无需填写真实业务信息。

## 个人如何编辑

推荐先修改 [03-personalization.txt](03-personalization.txt)：语气、目标、风险偏好、时间预算、保留现金、渠道偏好和角色侧重点。它是个人覆盖层，方便保留原版角色文件作为参考。

也可以直接编辑各角色文件里的“可编辑偏好”。例如 CFO 更重视现金、CMO 优先内容获客、CTO/Product 优先低维护方案。修改后，把**修改后的完整文件**重新提供给 AI；仅修改电脑里的文件不会自动更新当前对话。

用数值约束替代模糊标签，例如“每周最多投入 20 小时”“未经我确认不得增加月度订阅费用”。留空不表示无限预算。角色之间的经营偏好冲突时，应说明取舍，由创始人决定。

可以修改建议风格和经营规则，但不得把“大胆增长”“全权负责”等文字当成已经授权真实交易。缺失数据不能变成事实，估算不能伪装成确定结果。

## 文件导航

| 文件或目录 | 用途 |
| --- | --- |
| `00-controller.txt` | 启动、选择角色、协调分歧、汇总下一步 |
| `01-principles.txt` | 所有角色共用的数据、判断和权限原则 |
| `02-company-profile.txt` | 用户填写公司目标、资源、时间与数据来源 |
| `03-personalization.txt` | 用户可编辑的全局偏好和逐角色覆盖规则 |
| `roles/` | 八个角色各自的原则、功能、输出和协作方式 |
| `workflows/` | 周度经营复盘、营销预算决策、结果复盘 |
| `templates/` | 交接单、可手动保存的决策记录 |
| `examples/` | 仅含虚构数据的体验任务 |

## 与完整版本的区别

| 事项 | 提示词简易版 | 完整 Skill / 插件 |
| --- | --- | --- |
| 运行方式 | 复制文字到对话 | 安装后使用脚本与引用资料 |
| 数据校验 | 文字核对，不能声称通过 JSON Schema | 程序化结构和关联校验 |
| 计算 | 展示公式；有计算工具时核算，否则标为待复核 | Decimal 确定性计算与测试 |
| 历史记录 | 用户自行保存、下次附上 | 可选 JSON / SQLite |
| 真实执行 | 仅拟定待批准方案 | 有条件支持 GitHub issue；需独立审批 |

简易版已做内容、文件结构与链接检查；没有宣称在所有模型上完成行为测试。仓库保持私有，未授予开源许可证。
